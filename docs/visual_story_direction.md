# 絵を見れば話がわかる、論文動画の作り方

2026-10-04。対象は最新の **Native and Compact Structured Latents for 3D Generation**。

この動画で必要なのは、会話に合わせて情報を並べる図よりも、会話が説明する対象そのものを見せる絵である。原図を使えるようにする修正と、映像の作り方を変える設計を分けて記録する。現時点の試作は静止画であり、完成MP4の内容を更新したものではない。

## 実際に確認した問題

- 概要編の6場面すべてが補助図で、原図の使用はコードと生成指示の両方で禁止されていた。
- 原図の検査は、1枚でも合格すると残りを検査せずに完了した。最新論文には図2のわかりやすい車→O-Voxel→潜在表現の図も保存されていたが、使用候補になっていなかった。
- 圧縮の場面は「Spatial Downsampling」「Latent Space」「Sparse Conv」など6個の文字の箱で構成されていた。何を残し、何を減らすのかを絵で見せていない。
- 実験の場面は、データセット、比較手法、評価、ユーザー調査をフロー図として並べていた。これらの関係を処理順序と混同させる見せ方だった。
- 強調は主に箱の色替えで、原図の拡大指定は heat map という語への特殊対応だけだった。
- 図への指摘が一つでもあると、その場面の図を一般的なタイトルの箱に置き換えていた。修復よりも説明の欠落が起こりやすかった。
- たとえ話が風船、ネット、エンジン、写真、縫い物などへ移る。視聴者は技術とたとえの対応を毎回覚え直す必要がある。

「自然な英語を使う」「ユーモアを入れる」という指示だけでは、この構造的な問題は解消しない。C1の会話は維持し、映像側で追いやすくする。

## 今回反映した修正

1. 学会照合でリンクのないCVPR/ICCV受賞記録からも、著者名と題名を使って公式論文ページを探す。候補URLや受賞年だけでは確定せず、そのページの正確な題名・掲載学会・年を照合する。Test of Timeの受賞年はこの検索候補の年にも使わない。
2. 最新論文の掲載を公式記録で **CVPR 2026** と確認し、2本のタイトル、説明、サムネイルを修正する。音声とMP4本体は保持する。
3. 概要編と詳解編の両方で検査済みの原図を選択できる。構成と脚本の入力に原図一覧を渡す。
4. 原図の検査を候補ごとに続行する。合格済みの原図は再利用し、各候補の最大3回の修正と再開位置を保持する。
5. 会話の段落に `visual_focus_region` を記録し、検査済みの領域IDで拡大する。存在しない領域や未検査の原図は使用しない。
6. 拡大中は原図全体の小窓と拡大位置を残す。原図の文字や数値は書き換えない。
7. 図への指摘は有限回の図修正へ渡す。即座に一般的なタイトルカードに置き換える挙動をやめる。ただし修復しきれない場合の簡易図は残るため、以下の全面的な設計はまだ必要である。
8. 生成指示に、実物→注目箇所→理由の順序、一つの具体例、比較とフローの区別、その場の疑問から生まれる笑いを追加する。

## 次の生成方式：絵コンテを先に確定する

`根拠と原図 → 動画全体の問い → 各場面の絵コンテ → 図の描画と確認 → 絵に沿う会話 → 音声と字幕 → 動画確認`

脚本と図を同じ返答で一度に作る方式では、もっともらしい会話ともっともらしい図が別々に成立しやすい。各場面の絵コンテを保存し、その絵で説明できることを確定してから会話を作る方式へ進める。

各カットに次を持たせる。

| 項目 | 決めること |
| --- | --- |
| 視聴者の問い | この瞬間、何がわからないのか |
| 見せる対象 | 具体的な物体、原図、数式、比較のどれか |
| 気づいてほしい違い | 見る場所と、一つの違い |
| 出典 | 根拠ID、原図ID、検査済みの領域ID |
| 画面の変化 | 全体→拡大、前→後、入力→出力など |
| 説明の結論 | 見た違いから何が理解できるか |
| 会話の役割 | Aidenの疑問、Mayaの因果説明、軽い返し |
| たとえの限界 | 実物とたとえが一致しない点 |

動画全体では、一つの物体か使用例を追い続ける。新しい専門語は、見えているものの名前として導入する。途中で別の比喩を使う場合も、元の対象へ戻す。説明済みの意味を別の場面で言い直すより、次の疑問へ進む。

## 今回の論文なら、こう見せる

| 場面 | 主に見せるもの | 会話で解決する問い |
| --- | --- | --- |
| 冒頭 | 図1の実際の3Dエンジンとロボット | 今日の論文は何を作り、なぜ難しいのか |
| 課題 | エンジンの内部構造を拡大 | 表面がきれいなだけでは、何が足りないのか |
| 新しい表現 | 図2の同じ車を段階的に追う | 形と材質を、どう共通の表現へ持ち込むのか |
| 圧縮 | 同じ車の表現→小さな潜在表現→復元 | 小さくするとは、細部を全部捨てることなのか |
| 根拠 | 原図の比較・一つの代表的な実験 | 何を測り、どの条件で良かったのか |
| 限界と結末 | 確認できた失敗例か簡単な概念図 | 何はまだ難しいか。冒頭の問いへの答えは何か |

図2は一枚全部を貼るだけで終えず、車、O-Voxel、潜在表現の順に拡大し、短い英日ラベルを添える。圧縮と生成、復元を区別し、矢印が表す処理を明示する。図3には隣の本文や別の図が混入した切り出しがあるため、領域検査を通してから使う。

グラフは一度に複数指標を説明しない。まず横軸・縦軸の意味、次に比較条件、最後に見てほしい点を示す。数値を大きく見せる前に、その数値が何を測ったかを説明する。

## ユーモアは理解の役に立つ場所へ

推奨する形は **予想→軽い誤解→絵による訂正→短い返し**。Aidenは視聴者の疑問を具体的にする役、Mayaは仕組みを説明して少し返す役とする。Aidenを毎回無知な人にしたり、説明の合間に関係のない冗談を挟んだりしない。

例えば、原図のエンジンを示しながら、次のような掛け合いを設計できる。これは新脚本用の例で、完成動画のセリフではない。

> Aiden: “So a shiny surface isn't enough? The encoder can't file the inside under ‘optional ventilation’?”
>
> Maya: “Those gaps are part of the geometry. A prettier texture can't bring back a missing opening.”

次に内部構造を拡大し、形の情報と表面の見た目を分けて説明する。特定の旧手法が実際に穴を埋めたという結果は、この例から作り出さない。最後に同じ言葉を一度だけ回収すれば、動画全体にまとまりが出る。

英語の自然さは、長い文や難しい単語の量では決まらない。予想、疑問、訂正、結論の流れを自然な英語にする。使える表現を学習画面へ切り出す方針は維持する。

## 補助図の描画を変える

原図が得意なのは実物と実験の提示。補助図が得意なのは、目に見えない処理や変化を分解して見せること。全場面を同じ箱のテンプレートへ押し込まない。

- **形の表現**：同じ物体の輪郭、空間セル、必要なセルを順に表示する。
- **圧縮**：同じ対象の詳細表現と潜在表現の対応を見せる。単純な間引きやJPEGと同じ処理だと誤解させない。
- **比較**：同じ対象・条件・視点を横に並べ、違う箇所だけを強調する。
- **数式**：先に具体物と記号を対応させ、一つの演算ずつ表示する。
- **実験**：実際の原図・表を使い、結果の方向と実証範囲を説明する。

これらは固定のローカル描画テンプレートへ構造化データを渡して作る。任意のモデル生成コードは実行しない。画像モデルに科学的な比較結果や計算図を自由に描かせない。

動きは、情報が移る、対象が変わる、見る場所を示すために使う。装飾的なズームや文字の跳ねで、説明と字幕の読み取りを妨げない。画面上の英日ラベルは短く、詳しい説明は音声と字幕へ置く。

現在の図の指定は会話の段落単位である。次の方式では、一つの段落内にも「ここで全体を見せる」「この語で拡大する」というカットを持たせる。切り替え時刻をLLMに推測させず、脚本内の具体的な語句をASRの単語時刻へ対応させる。読んでほしい原図や比較には間を取り、話者交代だけを映像の編集点にしない。

## 自動確認を「文字が収まった」から進める

次の方式は設計段階。今回の静止画試作だけで、視聴者の理解やユーモアの改善を検証したとは扱わない。

1. 描画済みの画像をローカルの画像対応LLMへ渡し、「どの対象が、何から何へ変わったか」「どこを見れば話がわかるか」を回答させ、絵コンテの意図と照合する。
2. 文字の欠け、字幕との重なり、矢印の接続、領域ID、出典、比較条件はコードでも確認する。
3. 会話が言う対象・位置・変化が、実際のフレームに見えるか確認する。ラベルだけ一致する判定では不十分。
4. 音声付きの短い試写で、図を見る時間、字幕の読みやすさ、問いから答えへの間、笑いの位置を確認する。
5. 各単位の修正は最大3回。未確認の細部を外し、検査済みの原図か、意味を説明できる単純な図へ切り替える。工程と省略理由を保存し、無限修正や保留は避ける。

同じモデルが脚本を褒めたことだけで品質を保証しない。90秒程度の導入と、仕組みを説明する1場面の試写を残し、人が比較できるようにする。原図の比率を増やすだけではなく、視聴後に一つの問いへ答えられるかを確認する。

## 続く実装：改善版の概要動画1本

最初の検討に続き、`youtube-storyboard-2` の生成工程を追加した。

- 構成の後、各場面で「視聴者の問い・気づくべき点・原図または補助図・段階的な拡大・ユーモア」を独立した絵コンテとして保存する。
- 会話を書く前に実際のフレームを描画し、ローカルの画像対応LLMが見える対象と絵コンテの意図を確認する。修正は最大3回で、録音の割り込みは回数に含めない。
- 会話はその絵コンテと実際の描画画像を参照して作る。原図の注目箇所を段落単位で指定できる。
- 段落途中の画面切り替えは、脚本の語句をASRの単語時刻へ対応させる。動画側は音声の全サンプルと字幕の表示時間を保ったまま切り替える。
- 表面のセル、空間全体、形状と材質の違いを絵で示す、固定の `surface_cells` 補助図を追加した。2次元の模式図であり、圧縮後の実測結果として扱わない。
- 概要動画だけを1本作るAPIを追加した。従来どおり、本文のないリクエストでは2本を作る。
- 同じ論文の完成済みプロジェクトから本文の根拠を再利用する。旧脚本や音声は再利用しない。
- 参考文献の抽出は、PDFの二段組が混ざらないように読み、正式な題名を使う。Dora・Trellis・XCubeの元論文を実際に取得できた。
- 「3D」や学会の年を数字の誇張と誤判定する検査を修正し、数値を使った性能の約束と研究名を区別する。
- 原図のキャプションと検査済みのパネル情報を会話の検証へ渡す。画像中の凡例から手法を推測せず、旧手法の弱点を冗談のために架空の実験結果へ変えないようにする。
- 原図を拡大する際、比較グラフには確認済みの凡例を合わせる。原図そのものは書き換えず、長い領域名は画面で短く表示する。
- 同じフレームを指す絵コンテのカットは、画像確認時に重複入力しない。図番号・ページは確認済みの出典と照合し、画像だけから誤りと推測しない。
- 最大3回で簡易表示へ切り替える場合も、確認済みの拡大領域を維持する。制作指示を画面上の説明へ流用しない。

```bash
curl -X POST http://127.0.0.1:8190/api/papers/6b4eeb00dc3c4560b76b8ac63d88053c/video-projects \
  -H 'Content-Type: application/json' -d '{"modes":["overview"]}'
```

新しい形式の生成は同じ入力で重複開始しない。作成済み動画、旧教材、録音、停止中の旧ジョブを保持する。

## 完成した試作と実動画の確認（2026-10-05）

`a7297770703e45fb94f4a19f89385927` で、CVPR 2026の最優秀学生論文賞を受賞した **Native and Compact Structured Latents for 3D Generation** の概要解説を1本完成させた。

- 1920×1080、16分48秒、60.14 MB。書き出し版は `story-film-5-storyboard-captions`。
- 全6場面で原図を使用し、図1・2・3・5を扱う。花棚、生成例、比較グラフの拡大を音声に合わせ、グラフの凡例も主表示に含めた。
- 会話前の絵コンテと描画確認を保存。2場面は最大3回の確認後、確認済み原図と拡大へ切り替えて完成させた。
- 本文の既存根拠を再利用し、Dora・Trellis・XCubeの元論文を新たに取得して読んだ。旧動画の会話・音声は再利用していない。
- 最終確認で、開いた面と非多様体を混同するたとえ、および最後の繰り返し質問をローカルLLMで修正し、該当2段落の音声・字幕・練習を更新した。
- 日本語字幕ではカタカナ語をできるだけ分割せずに改行する。字幕描画コードのハッシュを動画入力に保存し、修正前の区間を混ぜない独立したMP4へ書き出した。
- 同じ音声の199文の練習、9個の英語表現、理解確認を用意。英日字幕は動画へ焼き込み済み。
- FLUX.2 klein Base 4Bでサムネイルを3案作成。論文名・CVPR 2026・概要解説・最優秀学生論文賞を表示した。確認できない「2D並みの速さ」という比較を使う旧候補は採用せず、今回は「『封じた泡』からの解放」を選んだ。
- 今後の字幕・会話・サムネイルにも適用するため、長い同一文の繰り返しを編集モデルへ明示し、サムネイルの作成と選定に主論文の根拠を別途渡すようにした。

実MP4の12時点で図・焼き込み字幕・口パクを含むフレームと音声を照合した。最大画素差0.555、音声相関0.99865以上、AACの音声差約21 msで同期検査を通過した。LANのHTTPS画面で1080p再生、MP4の範囲ダウンロード、サムネイル取得、同じ文章の練習再生、日本語訳の初期表示も確認した。
