# Nightly paper stories and local thumbnails

The library now includes **昨夜の動画**. In **Settings → 夜間に解説・詳解を自動作成**, set the start time (Japan time) and paper categories. This schedule is independent of the earlier chapter-lesson discovery switch. The production machine enabled **02:00 Asia/Tokyo** after both films in the first new-paper acceptance run completed and passed media/browser checks. Existing paused lesson jobs are retained.

The selected thumbnail is visible beside each completed film, with **サムネイル PNG** and **サムネイル JPEG** downloads. The three alternatives and regeneration controls remain in the detailed studio. **過去の夜間運転** also keeps the earlier films, selected thumbnail downloads and practice links available while a newer run is being built. Images are separate 1280×720 assets for YouTube's thumbnail upload field.

A run first checks official paper-award pages for the current and previous conference years. ICLR, ICML, NeurIPS, AAAI, RSS, ICRA, CoRL and IROS are the configured sources. Explicitly confirmed Best/Outstanding research-paper recipients are candidates, including student and systems prizes. Test of Time recipients are also eligible and have a separate award kind. Finalists, honorable mentions, runners-up and Classic awards are not promoted to winners. The source URL, page hash, award kind/name/year and retrieval time are saved. arXiv metadata must match the full normalized title unambiguously; unresolved papers are skipped with a reason. Recent award recipients can qualify even if their preprint predates the seven-day window. For Test of Time the window uses the award year, not the original publication year; at least one available recipient remains in the ten-candidate pool. The project and writing prompts preserve both dates, present the innovation in its historical setting and require evidence for later influence. See [the selection policy and measured checks](award_selection.md).

The worker also searches the last seven days of arXiv submissions and retrieves the Hugging Face Daily Papers community trending feed. It stores the source URL, rank, upvotes, publication date and retrieval time; awards and attention are not scientific evidence. Verified award recipients lead the ten-candidate shortlist, with a modest recent-domain balance preference. Up to three usable complete papers are read, including HTML equations, tables and captions (or PDF pages), then scored for the verified idea, evidence and storytelling potential locally. A suitable award recipient wins over an unawarded paper. When no suitable recipient is found, the reason is shown and recent papers are the fallback; the submission window can expand to thirty days. Previously filmed base arXiv IDs are excluded across revisions. **Settings → 最近のAI・ロボティクス学会の優秀論文賞・Test of Time賞を優先する** controls this policy independently of the nightly schedule, and each run snapshots the preference.

The chosen paper feeds the existing `paper-story-1` pipeline, with new dialogue and speech. Main-paper reading notes are reused as evidence, never as dialogue. Earlier research is retrieved from the bibliography and read in checkpointed complete-text batches, including its result tables, for historical context. Planning balances notes across references so one long paper does not displace the others. Reviews include passages cited by subsequent local repairs as well as the original outline evidence. The overview completes first; its MP4 and practice lesson are usable while the deep dive continues. Both receive original pixel actors, bilingual burned-in captions, variable pauses, local diagrams, sentence clips, expressions, comprehension questions and YouTube packaging. Uploading and publishing remain manual.

Both films now use `content-first-1`: enjoyment, clarity and a supported explanation take priority over runtime. There are no minimum/maximum minute targets or per-scene word quotas, no extra scenes merely to fill time, and no automatic speech acceleration to meet an upper limit. Scene editing still checks repetition, transitions, helpful examples and humor. The saved duration is a measurement, and finished cards show the actual runtime. The nightly schedule, recording priority and old paused lesson jobs are unchanged. See [the story pipeline](story_video_pipeline.md) for checkpoint compatibility.

## Recovery and bounded work

Creation takes a SQLite immediate transaction. A partial unique index keeps one scheduled run per Japan calendar day; explicit manual repeat runs are saved separately on the same date. **今すぐ論文を選んで作る** starts another paper after the current run has finished, retaining earlier films and history. Concurrent clicks reuse the unfinished run, including work carried over from a previous date. Schema version 6 migrates the former unique-day table transactionally while preserving IDs, project references and saved data. Repeated schedule ticks still reuse the original day's scheduled run. On boot, an enabled schedule catches up the current day once its start time has passed. It does not create a queue of missed dates. A previous unfinished automatic run, including a paused or failed project needing repair, prevents a new project from being added; that date records a skip reason.

The first run, whether scheduled or started manually, occupies that date's normal slot. Further manual repeats do not make the scheduler start the original run again. The production migration was backed up first and passed the foreign-key check. On 2026-10-03, a real LAN click started a new run without replacing the completed run, and all four selected PNG/JPEG downloads for the earlier two films returned image data successfully. Python 235 tests and browser 16 tests passed. [The acceptance record](../evaluation/manual_nightly_start.json) covers startup and downloads; the new films were still in production when it was recorded.

Collection, reading batches, selection, outlines, dialogue, speech, captions, render segments and thumbnail candidates are checkpointed. The worker uses its existing GPU owner and recording priority. Reader, speech and image actors share the card serially. Recording preemption and GPU waits do not consume repair attempts. Service shutdown is also an interruption rather than a malformed model result. A resumed job uses saved results; completed films remain available.

Network/model-response failures get at most three attempts per saved unit. Unavailable full texts move to the next candidate. Missing community attention falls back to arXiv without inventing popularity. Content repair falls back to supported explanations with omissions recorded. Image failures fall back to the original surprised pixel portraits and a simple local composition. A thumbnail's visual review can request up to three corrections, then selects the simple composition. Persistent storage/render failures are reported rather than polled forever. Manual retry can restart infrastructure work after fixing its cause.

## Thumbnail assets

Each film has three 1280×720 PNG/JPEG candidates. Maya is left and Aiden right, with enlarged surprised faces. Only eye and mouth areas can change in the original pixel portraits; the local compositor preserves hair, clothes, silhouette and palette. Generated central art is an illustrative metaphor, not paper evidence or a measurement chart. Large Japanese text and the smaller **英語で学ぶAI** label are added with local Noto CJK fonts after image generation.

New films use publication identity `paper-venue-edition-awards-2`: **【概要解説】full paper name｜conference year** or **【詳細解説】full paper name｜conference year**. A short hook follows when it fits YouTube's title limit; the full name is always retained separately. All three Japanese title suggestions, the recommended title, MP4 download name and description use this identity. The thumbnail format `surprised-pixel-3-awards` puts the full paper name in a wrapping upper band, the Japanese edition and conference/year in separate badges, and the large catchy Japanese headline below them. A separate gold badge shows the verified award's venue/year, Japanese name and full English name; it sits between the two faces. These fields are fixed renderer inputs, including the image-generation fallback, rather than text painted or inferred by the image model. Manifest identity and renderer hashes are saved. The renderer checks text overflow and badge overlap and rejects external browser requests.

Publication venue/year is verified from the title-matched official proceedings record, arXiv journal reference, or an explicit publication header on the original PDF's first page. RSS's individual official program pages also qualify when their paper heading matches exactly and the conference description and program URL agree on the edition year. Later Test of Time award dates and bibliography entries cannot supply this field. Confirmed records are saved with their source and reused without a network request. If confirmation is unavailable, **学会未確認** is displayed and generation continues; an improved lookup revisits an older unconfirmed record once without repeatedly blocking the worker. Existing movies and audio remain unchanged; new thumbnail regeneration uses the new composition. The current Asynchronous Methods project uses **ICML 2016**, independently of its 2026 Test of Time recognition. Deployment, LAN title checks, 1280×720 and 320×180 layout checks, and preserved script/audio checks are recorded in [publication_identity_acceptance.json](../evaluation/publication_identity_acceptance.json).

ICML, ICLR and NeurIPS virtual-program paper pages also qualify when the exact paper heading, official host, oral/poster/spotlight URL and explicit event title agree. This fixes The Flexibility Trap's **ICML 2026** identity. Award badges use only title-matched, source-hashed verified winners; finalists and unverified entries cannot add a badge. The official plural heading “Outstanding Papers” is displayed as “Outstanding Paper Award”, while the original heading and source remain recorded. Test of Time badges retain the later award year independently of the publication badge.

YouTube copy uses `paper-awards-no-urls-2`: paper title, publication conference, every verified award's full name and year, bilingual English-learning guidance, references as titles and arXiv identifiers, and the original timestamps. The generic local-AI-production/hypothetical-example disclosure is omitted from the copy. No URLs are exported in the description or its downloadable text file. Provenance URLs remain in the internal paper/award records. Both previews and complete films use the same description builder. `scripts/refresh_video_packaging.py PROJECT [PROJECT ...] --thumbnails` refreshes completed films from saved local illustrations and protected portraits without model inference or reencoding video/audio. It retains old sets and description history, preserves the selected candidate, verifies unchanged MP4 hashes, and records the result. The thumbnail composition runs inside the local inference network guard, with external Chromium requests blocked. Run it only for completed projects; ordinary generation and recording priority remain managed by the worker.

The pipeline additionally uses release policy `verified-video-packaging-1`. Manual and nightly film snapshots now call the same verified-identity preparation as thumbnail snapshots. A rendered MP4 enters **checking** before **ready**: the worker checks its actual poster, title, URL-free description and downloadable text file. It repeats these checks when resuming a completed export, before advancing to the next film, and before marking the nightly run complete. Results and any automatic repairs are retained in each export's `release_check` and are available through the project API. A thumbnail model job can continue while a completed film and its English practice are usable: the temporary poster uses the fixed local pixel compositor with the same paper, edition, conference and award fields. It does not require image-model inference.

Every composed thumbnail writes a `thumbnail-dom-check-1` receipt with text read from the actual DOM, the overflow result, 1280×720 dimensions and hashes of the PNG, JPEG, renderer and input. The checker compares those rendered fields with the confirmed paper/award records, so a database **ready** flag or the model's own review alone cannot approve an outdated or incomplete image. Missing receipts, wrong fields and changed image bytes trigger local recomposition from saved art; unavailable art uses the checked fixed composition. Old sets and manual choices remain available. Copy repair merges into the latest export so a concurrent user selection is preserved. Chromium renders this fixed 2D composition without the inference GPU and retries a transient screenshot-capture failure at most three times. Persistent rendering/storage failures retain the worker's existing bounded retry and visible error behavior.

An unconfirmed publication lookup is cached against its source inputs, rather than just the lookup-code version. Newly saved proceedings metadata, journal references, PDF updates or official paper links trigger a new lookup. A title-matched confirmed paper record is reused immediately, including after restart. Missing confirmation remains explicit as **学会未確認**; neither the LLM nor an award date fills in a guessed publication year.

Regression tests include omitted fields at enqueue, an actual offline fallback poster before image-model completion, a resumed **ready** export with stale copy, changed PNG/JPEG/inputs, late publication evidence, concurrent manual selection and a nightly completion with missing saved thumbnail inputs. The image model is [FLUX.2 klein Base 4B](https://huggingface.co/black-forest-labs/FLUX.2-klein-base-4B), revision `a3b4f4849157f664bdbc776fd7453c2783562f4d`. Its official card identifies Apache 2.0 and reference-image editing support. Base sampling uses BF16, 50 steps and guidance 4.0; seed, prompt hash, model revision, output hash and final portrait hashes are saved. Model files are individually hashed in `models.lock.json`. `.venv-image` is independent of ASR/TTS environments; `locks/image.txt` fixes dependencies with package hashes. `scripts/setup.py` and `scripts/prepare_assets.py image` reproduce acquisition. No Qwen-Image 2.1 or paid inference service is used.

The model loads from local files with HF offline settings. The worker and image actor run inside the application's loopback-only inference socket guard, and Chromium rejects network requests while rendering. Acquisition intentionally uses the internet. This restriction covers the application's inference process, rather than changing the machine's firewall or preventing unrelated applications from using the network.

The local multimodal reader recommends one candidate after checking the actual film's promise, recognizable faces and small-screen typography. The film card offers **この案を使う**, PNG/JPEG downloads and **3案を再生成**. Manual choices survive refresh and automatic review. Regeneration retains previous sets and the current poster until a replacement is ready. Selection updates poster metadata without reencoding MP4 or speech. Older work-directory posters receive retained public copies. Backup/restore includes the candidates, portrait cache, histories and nightly records.

## API and verification

- `GET /api/nightly-video-runs`: fourteen recent runs, selection reasons, checkpoints, timings and both film states.
- `POST /api/nightly-video-runs`: idempotent manual start for today.
- `GET /api/video-projects/{id}`: existing project with each film's thumbnail set and selected/recommended IDs.
- `POST /api/video-projects/{id}/thumbnails`, body `{"mode":"overview"}` or `deep_dive`: create another three-candidate set.
- `PUT /api/thumbnail-sets/{id}/selection`, body `{"candidate_id":"..."}`: select a ready image.
- Existing `/api/jobs/{id}/pause|resume|retry|cancel` and SSE apply; nightly controls cascade to their project, renderer and thumbnail jobs.

Run the Python tests, frontend build and Playwright tests before deployment. `scripts/nightly_browser_acceptance.mjs PROJECT` checks the actual LAN UI, all image downloads, 1280×720 dimensions, saved manual selection and a 320 px contact sheet. `scripts/story_acceptance.py PROJECT --screenshots --sync` inspects finished media and aligns actual audio/frames; `scripts/story_browser_acceptance.mjs` covers playback and same-script English practice. File-fed microphones check browser capture and local evaluation, not human pronunciation accuracy or physical Mac hardware.

Live acceptance results and measured durations are recorded in `docs/nightly_video_verification.md` after both new-paper films finish. Active-stage timing sums exclude interrupted units; total elapsed time includes restarts, recording interruptions, queue waits and verification work.
